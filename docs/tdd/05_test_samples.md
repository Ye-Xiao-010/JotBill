# 05. 测试样本采集方案

> 技术实现文档(TDD)第五部分
>
> 关联文档:04_phase1_tasks.md 第3节测试样本、01_ai_provider_adapter.md
>
> 作用:定义阶段一所需测试样本的采集流程、脱敏规则、合成数据规范、命名约定和管理方法,确保 AI 能力验证在真实且合规的数据上进行

---

## 1. 目标与范围

### 1.1 目标

为阶段一"AI 能力验证"提供 **不少于 10 张真实结算页截图 + 不少于 5 张合成/补充截图** 的样本集,用于:

- 验证三家 AI 服务商(通义千问、智谱 GLM、硅基流动)的识别准确率
- 测试 Prompt 在不同平台、不同场景下的稳定性
- 评估图片压缩对识别结果的影响
- 为阶段二、三提供回归测试基线

### 1.2 范围

| 包含 | 不包含 |
|---|---|
| 真机截图采集流程 | 模拟器截图(分辨率/DPI 不一致) |
| 敏感信息脱敏规则 | 真实订单数据外传 |
| 合成截图生成方案 | 自动化批量真实下单 |
| 样本元数据格式 | 训练数据集(本项目不训练模型) |
| 样本版本管理 | 公开数据集爬取 |

### 1.3 合规边界

- 所有真实截图必须来自 **本人自有账户的订单**,不得采集他人设备或他人账户的截图。
- 脱敏后的截图方可提交给 AI 服务商;原始未脱敏截图 **禁止上传任何外部网络**。
- 样本集仅存储在项目根目录下的本地 `phase1-test\samples\`,不入 Git 仓库,不上传云盘。
- 合成截图使用虚构平台名、虚构商户名、虚构金额,与现实商户无关。
- 样本集仅用于本项目的 AI 能力验证,不用于其他用途,不公开发布。

## 3. 真机采集流程

### 3.1 准备工作

**步骤 1:清理后台**

- 重启手机或清理近期任务,确保被测 App 以冷启动状态进入结算页
- 关闭悬浮窗、通知权限弹窗等可能干扰截图的元素

**步骤 2:开启开发者选项截图快捷方式**

- 设置 → 我的设备 → 全部参数与信息 → 连续点击 MIUI 版本 7 次
- 设置 → 更多设置 → 开发者选项 → 启用"快捷截屏"或使用三指下拉截屏

**步骤 3:准备订单**

- 在被测平台(APP 内或网页)走完下单流程,到达 **结算页/确认订单页**(此时未实际支付)
- 滴滴、美团到店等场景可在历史订单中查看结算页

### 3.2 截图操作

**标准采集方式(三指下拉截图):**

1. 进入目标结算页
2. 等待页面完全加载(等待 2 秒,确保图片和文字渲染完成)
3. 三指下拉触发截图
4. 立即点击截图预览的"编辑"按钮,进入编辑模式
5. 执行第 4 节的脱敏操作
6. 保存到相册的 `Screenshots` 目录

**长截图采集(仅用于 `*_long_01.jpg`):**

1. 在长列表结算页执行标准截图
2. 在截图预览中点击"长截图"按钮
3. 缓慢向下滚动覆盖全部商品
4. 保存

### 3.3 采集后检查

每张截图采集后立即检查:

| 检查项 | 通过标准 |
|---|---|
| 完整性 | 结算页顶部、金额、底部按钮全部可见 |
| 清晰度 | 文字无明显模糊,可读 |
| 方向 | 竖屏,无旋转 |
| 尺寸 | 分辨率不低于 1080×1920 |
| 脱敏 | 已按第 4 节完成敏感信息遮盖 |
| 文件格式 | JPEG(JPG),非 PNG(统一格式) |

不合格者立即重采,不留待后期处理。

## 4. 敏感信息脱敏规则

### 4.1 必须遮盖的字段

| 字段 | 位置示例 | 遮盖方式 |
|---|---|---|
| 收货人姓名 | 结算页顶部地址栏 | 实心矩形覆盖,保留"先生/女士"字样可选项 |
| 收货电话 | 地址栏电话 | 实心矩形覆盖整段 |
| 收货地址 | 地址栏详细地址 | 保留省市,遮盖门牌号以下 |
| 用户头像 | 顶部状态栏、底部导航 | 实心矩形覆盖 |
| 用户昵称 | 顶部状态栏 | 实心矩形覆盖 |
| 订单编号 | 结算页底部"订单号"字段 | 可整段遮盖(测试不依赖订单号) |
| 支付二维码 | 若结算页含支付码 | 整段遮盖 |
| 银行卡尾号 | 若显示支付方式 | 保留"招商银行/工商银行",遮盖尾号 4 位 |
| 优惠券码 | 若显示完整券码 | 遮盖中间 6 位以上 |

### 4.2 不可遮盖的字段

以下字段是 AI 识别的目标,**禁止遮盖**:

- 商品名称
- 商品数量
- 商品单价(可选,不强制)
- 应付金额/实付金额/总价(主目标)
- 商户名(外卖/到店场景)
- 平台标识(顶部导航的 App 名/Logo 区域)

### 4.3 脱敏工具

**首选:小米相册内置编辑器**

- 截图后立即在预览中点击"编辑"
- 选择"马赛克"或"涂抹"工具
- 选择 **实心黑色矩形**(不要用模糊马赛克,模糊后可能被还原)
- 遮盖范围应略大于敏感文字范围,确保边缘无残留

**禁止使用的方式:**

- 模糊马赛克(可被深度学习还原)
- 涂抹笔刷半透明(底层文字仍可识别)
- 仅裁剪边缘(可能漏掉关键字段)

### 4.4 脱敏后复核

每张截图脱敏后,执行以下复核:

1. **肉眼复核**:放大到 200%,逐字段检查遮盖是否完整
2. **OCR 复核**(可选):用小米相册的"识别文字"功能,确认遮盖区域不被识别出任何字符
3. **元数据清理**:用文件管理器查看图片属性,删除 EXIF 中的位置信息、设备信息(小米相册默认不带 EXIF,但需确认)

### 4.5 脱敏失败处理

若发现脱敏不完整:

- 立即删除当前截图文件
- 重新从原始截图编辑(若原始文件已删除,需重新采集)
- **禁止**将未脱敏截图临时存放于任何目录

## 5. 合成截图生成方案

### 5.1 用途

合成截图用于:

- 补充真实样本无法覆盖的平台(如已卸载的 App)
- 测试极端场景(超大金额、超长商户名、特殊字符)
- 测试 Prompt 的边界条件(空字段、异常金额)
- 提供无任何隐私风险的样本用于回归测试

### 5.2 合成原则

| 原则 | 说明 |
|---|---|
| 虚构化 | 平台名、商户名、商品名全部虚构,不得使用现实商户 |
| 风格化 | 模仿真实结算页的版式(顶部导航、商品列表、金额栏、底部按钮) |
| 多样化 | 覆盖浅色/深色、单品/多品、含券/不含券等组合 |
| 标注化 | 文件名以 `synthetic_` 前缀,元数据中 `source=synthetic` |

### 5.3 合成清单(不少于 5 张)

| # | 文件名 | 模拟平台 | 模拟场景 | 测试目的 |
|---|---|---|---|---|
| S1 | `synthetic_checkout_large_amount.jpg` | 虚构电商 | 高金额(99999.99) | 测试大金额识别 |
| S2 | `synthetic_checkout_special_char.jpg` | 虚构外卖 | 商户名含特殊符号 | 测试特殊字符 |
| S3 | `synthetic_checkout_long_merchant.jpg` | 虚构到店 | 超长商户名(20字以上) | 测试截断处理 |
| S4 | `synthetic_checkout_zero_amount.jpg` | 虚构电商 | 金额为 0(全额抵扣) | 测试边界 |
| S5 | `synthetic_checkout_dark.jpg` | 虚构电商 | 深色模式 | 测试深色主题 |
| S6 | `synthetic_checkout_multi_line.jpg` | 虚构外卖 | 多行商品名 | 测试长文本 |

### 5.4 合成工具

**方案 A:Figma / Sketch(推荐)**

- 制作结算页模板(顶部导航 + 商品卡 + 金额栏 + 底部按钮)
- 导出为 1440×3200 PNG,再转换为 JPEG 质量 90
- 优点:版式精确可控,可复用模板
- 缺点:需要设计基础

**方案 B:Android XML 布局渲染**

- 写一个简单的 Activity 布局模拟结算页
- 在真机或模拟器上运行后截图
- 优点:真实渲染效果
- 缺点:开发成本较高

**方案 C:HTML + Playwright 截图(快速原型)**

```html
<!-- 示例:虚构电商结算页 -->
<div class="checkout-page">
  <div class="nav-bar">MockShop</div>
  <div class="product-list">
    <div class="product">
      <span class="name">虚构商品 A</span>
      <span class="qty">×2</span>
      <span class="price">¥199.00</span>
    </div>
  </div>
  <div class="amount-bar">
    <span class="label">应付金额</span>
    <span class="amount">¥398.00</span>
  </div>
  <div class="submit-btn">提交订单</div>
</div>
```

- 使用 Playwright 在 1440×3200 视口下截图
- 优点:快速、可脚本化批量生成
- 缺点:版式与真实 App 有差异

### 5.5 合成样本的元数据

合成样本的 `expected.json`(见第 6 节)中必须包含:

```json
{
  "source": "synthetic",
  "tool": "figma|android|playwright",
  "designNote": "商户名故意使用 25 个字测试截断"
}
```

## 6. 样本元数据格式

### 6.1 单张样本元数据

每张样本图片 `<name>.jpg` 配套一份 `<name>.json`,格式:

```json
{
  "fileName": "jd_checkout_01.jpg",
  "source": "real|synthetic",
  "platform": "京东",
  "scenario": "电商单品",
  "expected": {
    "amountMinor": 9900,
    "currency": "CNY",
    "platform": "京东",
    "merchant": null,
    "productDescription": "手机壳×1",
    "isCheckoutPage": true
  },
  "capture": {
    "device": "Xiaomi 17U",
    "androidVersion": "16",
    "resolution": "1440x3200",
    "dpi": 560,
    "orientation": "portrait",
    "theme": "light"
  },
  "redaction": {
    "applied": true,
    "fields": ["recipientName", "phone", "addressDetail", "orderId"],
    "verifiedBy": "manual+ocr"
  },
  "notes": "多品合并下单,含 1 张优惠券",
  "createdAt": "2026-08-04T10:30:00+08:00"
}
```

### 6.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `fileName` | string | 是 | 与图片文件名一致(含扩展名) |
| `source` | enum | 是 | `real`(真机采集) 或 `synthetic`(合成) |
| `platform` | string | 是 | 真实平台名或虚构平台名 |
| `scenario` | string | 是 | 场景描述 |
| `expected.amountMinor` | integer | 是 | 预期金额(最小货币单位),阶段一所有样本均为正整数 |
| `expected.platform` | string | 是 | 预期平台识别结果,阶段一所有样本必须非空 |
| `expected.merchant` | string/null | 是 | 预期商户(电商可空) |
| `expected.isCheckoutPage` | boolean | 是 | 是否为结算页,阶段一所有样本均为 true |
| `capture.*` | object | 真实样本必填 | 采集设备信息 |
| `redaction.applied` | boolean | 真实样本必填 | 是否已脱敏 |
| `redaction.fields` | array | 真实样本必填 | 已脱敏字段列表 |
| `notes` | string | 否 | 备注 |
| `createdAt` | ISO8601 | 是 | 采集/生成时间 |

### 6.3 样本集索引文件

在 `samples/` 目录下维护 `index.json`,汇总所有样本:

```json
{
  "version": "1.0.0",
  "updatedAt": "2026-08-04T11:00:00+08:00",
  "totalCount": 15,
  "realCount": 10,
  "syntheticCount": 5,
  "items": [
    { "fileName": "jd_checkout_01.jpg", "platform": "京东", "source": "real" },
    { "fileName": "synthetic_checkout_large_amount.jpg", "platform": "MockShop", "source": "synthetic" }
  ]
}
```

## 7. 命名规范

### 7.1 文件名规则

```
<平台或类型>_<场景>_<序号>.jpg
```

- 全小写,下划线分隔
- 平台名使用英文(`jd`/`taobao`/`meituan`/`pdd`/`didi`/`eleme`)
- 场景名使用英文(`checkout`/`waimai`/`dadian`/`dark`/`promo`/`long`)
- 序号两位数字(`01`/`02`/`03`)
- 合成样本以 `synthetic_` 前缀

### 7.2 示例

| 文件名 | 含义 |
|---|---|
| `jd_checkout_01.jpg` | 京东结算页第 1 张 |
| `meituan_waimai_01.jpg` | 美团外卖场景第 1 张 |
| `taobao_checkout_02.jpg` | 淘宝含优惠结算页第 2 张 |
| `synthetic_checkout_dark.jpg` | 合成的深色模式结算页 |

### 7.3 禁止的命名

- 中文文件名(可能导致跨平台编码问题)
- 空格、特殊符号(仅允许字母、数字、下划线、点)
- 大写字母(统一小写,避免大小写敏感问题)

## 8. 样本管理

### 8.1 目录结构

```
phase1-test\
├── samples\
│   ├── index.json                       (样本集索引)
│   ├── jd_checkout_01.jpg
│   ├── jd_checkout_01.json
│   ├── jd_checkout_02.jpg
│   ├── jd_checkout_02.json
│   ├── ... (其余真实样本)
│   ├── synthetic_checkout_large_amount.jpg
│   ├── synthetic_checkout_large_amount.json
│   └── ... (其余合成样本)
├── samples_raw\                          (可选,原始未脱敏,仅本机)
│   └── .gitignore                        (内容: *)
├── results\
│   └── test_results.csv
└── README.md                             (采集说明,不包含敏感信息)
```

### 8.2 Git 忽略规则

在项目根目录 `.gitignore` 中添加:

```
# 阶段一测试样本(含真实脱敏截图,不入库)
phase1-test/samples/
phase1-test/samples_raw/
phase1-test/results/

# 测试结果 CSV
phase1-test/results/*.csv
```

仅 `phase1-test/README.md`、`samples/index.json`(可选,需确认无敏感信息)、代码文件入库。

### 8.3 版本管理

- 样本集采用 **版本号** 管理,在 `index.json` 中记录
- 重大修改(替换样本、修改预期值)递增次版本号(`1.0.0` → `1.1.0`)
- 新增样本递增修订号(`1.0.0` → `1.0.1`)
- 删除样本需递增次版本号,并在 `CHANGELOG.md`(若存在)中说明原因

### 8.4 备份策略

| 备份项 | 位置 | 频率 | 加密 |
|---|---|---|---|
| 脱敏后样本 | 本机 `samples\` | 实时 | SQLCipher 不适用,依赖磁盘加密 |
| 脱敏后样本副本 | 移动硬盘(可选) | 采集完成后 | BitLocker 加密分区 |
| 原始未脱敏样本 | 本机 `samples_raw\` | 立即删除策略 | — |
| 元数据 JSON | 本机 + Git | 每次更新 | — |

**原始未脱敏样本的处理:**

- 脱敏完成后立即从 `samples_raw\` 删除原始文件
- 清空回收站
- 仅在脱敏失败需重新编辑时,保留原始文件不超过 24 小时

### 8.5 销毁策略

阶段一验收通过后:

- 真实脱敏样本保留,作为阶段二、三的回归测试基线
- 原始未脱敏样本(若仍存在)立即删除
- 合成样本长期保留
- 若项目终止,所有真实样本(含脱敏版)从本机和备份中永久删除

## 10. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 真实订单不足覆盖所有平台 | 中 | 样本数不足 | 用合成样本补充,但真实样本不得少于 8 张 |
| 脱敏不彻底导致隐私泄露 | 低 | 严重 | 双重复核(肉眼 + OCR),失败立即删除重采 |
| 截图分辨率/DPI 不一致 | 中 | 识别结果偏差 | 统一使用小米 17U 采集,合成样本按 1440×3200 生成 |
| 平台 App 更新导致结算页版式变化 | 中 | 样本失效 | 在 `index.json` 记录 App 版本号,版本变化时重新采集 |
| 样本被误传至 Git 仓库 | 低 | 隐私泄露 | `.gitignore` 配置 + 提交前检查 + 使用 `git status` 确认 |
| 合成样本与真实版式差异过大 | 中 | 测试结果不具代表性 | 合成样本仅作补充,验收以真实样本为准 |
| 长截图拼接处文字错位 | 低 | 识别失败 | 避免使用长截图作为主样本,仅作补充 |
