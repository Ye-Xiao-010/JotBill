# JotBill 测试指南
> **状态**：[参考] —— 稳定
> 入口：`00-现状正本.md`

## 测试状态

阶段一 AI 视觉能力验证已由项目负责人完成。本仓库不重复采集样本、不重复调用三家 AI 服务商，也不把真实截图或 API Key 提交到 Git。

阶段一的样本和验证报告由项目负责人保存；阶段二开始后，新增测试必须使用脱敏或合成数据。

## 测试层级

### 当前迁移基线

```powershell
npm run backend:test
npm run backend:test:e2e
npm run mobile:test
```

这些测试只覆盖 LiteNote 基线，不能证明 JotBill 本地化功能可用。

### 阶段二必须新增

- Room Entity 和 DAO CRUD 测试。
- 金额分单位转换测试。
- 外键、索引、唯一约束和事务回滚测试。
- SQLCipher 数据库打开失败测试。
- Native Module DTO 序列化和错误码测试。
- RN 调用 Native Module 的分页、版本冲突和缓存失效测试。
- AI 配置加密存储和 API Key 脱敏日志测试。
- 离线状态下账单、分类、账户和统计页面测试。
- JotBill 包名、权限、开机启动和真机安装测试。

## 阶段二验收重点

1. `com.jotbill.app` Debug APK 能在基线真机安装和启动。
2. Room 数据库能创建、迁移、加密和恢复。
3. 账单写入同时更新账户余额并生成审计记录。
4. 同一账单或候选不能被重复提交。
5. RN 与原生层字段严格符合 `docs/types/Native.d.ts`。
6. 账单、分类、账户、预算和统计页面在断网时仍能工作。
7. 抓包确认账本数据不再发送到 LiteNote 后端。

## 隐私测试

- 测试日志不得包含 API Key、截图 Base64、原始通知、短信或完整账单文本。
- 测试设备上的真实截图只存在于私有本地目录。
- 测试结束后清理未脱敏文件、临时导入文件和导出的备份。
- 失败报告使用错误码和脱敏字段，不附带原始支付凭证。
